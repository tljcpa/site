某高校举办的具身智能比赛，初赛是 LIBERO Object 仿真任务：用官方给的 LeRobot 数据做模仿学习，指标是隐藏任务上的成功率。训练必须在官方指定的天数智芯（国产 GPU）算力平台上完成。

先说边界：**没有拿到可报的名次，也没有完成计划中的 π0.5 训练**。实际跑起来的是 π0 的 LoRA 续训，停在第 7500 步。下面写的是做成了什么、卡在哪里。

## 数据

官方数据包是 LeRobot v2.1 格式，536,398,466 字节：

- Franka 机械臂，10 个物体搬到篮子里的任务。
- 454 条 episode，66,984 帧，908 段视频，20 FPS。每条 114 到 254 帧。
- 主相机和腕部相机各一路，256×256 RGB，AV1 编码。
- 状态 8 维，动作 7 维（位置、轴角旋转、夹爪）。

## 做了什么

### 数据格式转换

不同 VLA 代码库要的格式不一样，所以写了 LeRobot 转 OpenDM 和 LeRobot 转 RLDS 两个转换工具。转换不改数值、符号、尺度和顺序。

OpenDM 这一路做了全量转换和核验：

- 66,984 行逐一和原始 parquet 精确比对。
- 133,968 张 JPEG 全部实际加载一遍。
- 转换时传入预期的帧数和 episode 数，对不上就报错。结果是 454 episode、66,984 帧，没有主动排除，也没有来历不明的丢帧。

还发现一个坑：OpenDM 内置的 `libero_object` 注册按 7 维状态写的，这份数据是 8 维，必须改用 `libero_pi0_all` 注册。

RLDS 这一路写好了转换和校验，但 TFDS 数据集还没有真正生成。

### 让 PyTorch 在国产 GPU 上跑起来

平台节点上原本的 PyTorch 是 NVIDIA CUDA 发行版，和天数 GPU 不兼容。换用节点自带的 COREX PyTorch，只改训练进程的库路径和 Python 搜索路径，不动系统安装。

换完之后先跑一次 10 步的 smoke 测试。第一次在导入 LeRobot 时因为缺 `pyserial` 退出，补上后第二次通过：第 6000 到 6010 步退出码 0，10 步 loss 全部是有限值。

### 可续训的检查点

续训的起点是之前一轮留下的第 6000 步 LoRA 检查点。恢复时检查了这些：

- 基模加载 778 个张量，没有缺失和多余的键。
- adapter 514 个张量逐一比对相等且有限，可训练参数 26,674,688 个。
- optimizer、RNG、scheduler 都真正恢复，没有重新初始化。

正式续训每 100 步保存一次 adapter、optimizer、RNG、scheduler 和配置，每次保存都写一份 `complete.json`，记录每个文件的字节数和 SHA256。以这份文件作为保存完成的依据。

### 备份工具

平台机器随时可能被回收，所以写了独立的备份脚本，每 60 秒检查一次新检查点，传回本地后重新计算 SHA256 比对。截止第 7500 步的检查点都已在本地校验通过。

中途发现交接记录里的一个 SHA256 有一处字符写反了，对远端原包和传输副本分别重算后改正。

## 训练记录

- smoke（batch 4）：第 6001 步 loss 0.8123，第 6010 步 0.5044，每步约 2.7 到 3.1 秒。
- 正式续训（batch 16，单卡）：第 6011 步 loss 0.5166，第 6024 步 0.5878。每步约 9.6 到 9.85 秒，显存约 20GB（卡 32GB），没有 OOM，GPU 利用率 98% 到 100%。
- 第 7395 步最近 loss 0.2932。
- 训练停在第 7500 步，原计划是 9000 步。

loss 是单步数值，有波动，只能看趋势。

## 为什么停在 7500 步

目标本来是 π0.5。训练跑了一段后核对配置，发现恢复的基模配置标的是 `policy.type=pi0`，不是 π0.5。确认选错后主动停掉了这次训练，最后一个完整检查点是第 7500 步。

之后准备了另外两条路线：DM0.5（OpenDM）的 LoRA 微调和 TurboVLA。DM0.5 的数据已经转好，但官方权重下载到约 0.60/11.66GB 时超时，GPU smoke 和训练都没启动。TurboVLA 只做到源码核对和训练脚本，没有生成数据，也没有训练。

## 诚实边界

- 没有名次可报，也没有提交成绩可以引用。
- 没有在仿真里评测续训后的模型，所以没有成功率数字，loss 下降不等于任务成功率提升。
- 实际训练的是 π0，不是 π0.5。选错基模到发现，浪费了一段算力。
- RLDS 转换和 DM0.5、TurboVLA 两条路线都停在准备阶段。
- 没有做任何对照实验。
